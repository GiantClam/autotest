# Tauri macOS AI 测试修复 PoC 实现计划

状态：规划完成，第一期采用 Agent-first 方式，等待进入实现阶段。

## 需求摘要

- 目标对象：现有业务 Tauri 应用。
- 执行环境：本机 macOS；第一期不做云端、不做远程桌面、不做 Ubuntu/Windows/移动端。
- 启动方式：从业务应用代码仓库启动开发版，沿用现有固定脚本。
- 首条流程：创建一条记录 → 保存 → 关闭并重新启动应用 → 验证记录仍存在且字段完全一致。
- 数据：本地 SQLite 或本地文件；每次运行使用唯一测试标识并自动清理。
- 操作边界：只允许操作目标 Tauri 应用、必要系统弹窗和应用重启控制。
- 决策方式：先生成结构化测试流程，再逐步观察并执行。
- 模型：Sonnet 负责规划、失败分析和修复建议；Jev 负责动作选择。
- 修复：先寻找真实业务缺陷；AI 直接修改当前工作分支；最多自动修复 2 轮；测试通过后自动提交。
- 可视化：本机前台可见真实鼠标移动、点击和输入，同时保存动作时间线、截图、日志和 Trace；不做远程接管。

## 执行模式调整

第一期不编写独立 Runner。直接在本机 Mac 上运行 Codex 或 Claude Code，由 Agent 负责：

- 读取测试目标和结构化场景。
- 调用 `agent-desktop` MCP 或 CLI。
- 观察 Accessibility Snapshot 和应用状态。
- 逐步执行点击、输入、重启和断言。
- 读取日志、截图和 Trace。
- 分析真实缺陷、修改当前分支、复测并自动提交。

这条路径用于最快验证核心闭环。测试记录先使用 Agent 对话记录、`agent-desktop` Trace、截图和 Git Diff 保存，不建设任务队列、后台 Worker 或独立状态机。

只有在 PoC 通过后，才考虑把稳定的动作和断言抽取成薄 Runner，用于重复执行、无人值守、定时任务和云端多租户。

## 关键技术决策

1. 第一阶段由 Codex 或 Claude Code 直接承担测试编排，不把测试逻辑散落到 Tauri 页面代码中。
2. 通过 `agent-desktop` CLI 或 MCP 执行桌面动作；模型输出先转换成受限的结构化动作，再交给执行器。
3. 第一阶段使用对话记录、Trace、截图、日志和 Git Diff 作为证据，不先实现独立事件数据库。
4. 先验证 Tauri WebView 的控件是否能出现在 macOS Accessibility Snapshot 中。若 WebView 内容不可见，保留 CDP/Playwright 适配器作为兜底，不扩大桌面操作权限。
5. 修复流程必须在原始测试失败、补丁应用、原流程复测和回归通过后才自动提交。

## 后续可抽取的代码模块

以下模块不是第一期前置工作，只在 Agent-first PoC 通过后按需要抽取；实际文件路径需在拿到 Tauri 仓库后按现有结构落位：

- `config/app.local.*`：开发启动命令、关闭/重启方式、应用标识、数据清理脚本。
- `src/runner/`：任务状态机、超时、暂停、重试和生命周期。
- `src/adapters/agentDesktop.*`：权限检查、snapshot、动作执行、窗口聚焦和应用重启。
- `src/scenario/`：测试 DSL、模板变量、前置条件、步骤和断言。
- `src/evidence/`：截图、鼠标/点击事件、Trace、日志和事件索引。
- `src/models/`：Jev/Sonnet 适配、模型调用记录、结构化输出校验和脱敏。
- `src/findings/`：失败分类、复现步骤、严重性和证据关联。
- `src/repair/`：读取当前分支、生成修改、最多两轮复测、自动提交。
- `src/ui/`：本地可视化控制台，显示运行状态、当前步骤、截图、事件时间线和失败证据。
- `scripts/`：权限自检、启动/关闭/重启、测试数据清理和本地验证命令。

## 执行步骤

### 1. 直接使用 Agent 建立本机运行契约

- 检查 macOS Accessibility、Screen Recording 和 Automation 权限。
- 确认 `agent-desktop`、Node/Python、模型客户端和 Tauri 开发依赖可用。
- 将现有启动脚本、关闭方式、重启方式和数据清理方式记录在本次 Agent 运行上下文中。
- 确认运行时只聚焦目标 Tauri 应用。

### 2. 验证 Tauri 可观测性

- 启动开发版应用。
- 获取窗口列表和 Accessibility Snapshot。
- 验证记录列表、创建按钮、输入框、保存按钮和结果区域是否有稳定的可引用节点。
- 若节点缺失，记录缺口并启用 CDP/Playwright 或截图视觉适配器；不直接进入自由坐标点击。

### 3. 在 Agent 上使用最小结构化测试流程

先支持以下动作：`launch`、`focus`、`snapshot`、`click`、`type`、`wait`、`assert`、`restart`、`cleanup`、`capture`。

首条场景固定为：

1. 启动应用。
2. 创建唯一测试记录。
3. 填入固定字段。
4. 保存。
5. 关闭应用。
6. 重新启动应用。
7. 查找唯一测试记录。
8. 断言所有字段完全一致。
9. 清理测试记录。

### 4. 在 Agent 中接入 Jev + Sonnet

- Sonnet 生成结构化场景、解释失败、提出修复假设。
- Jev 根据当前 snapshot 选择下一个目标和动作。
- 所有动作必须通过 JSON Schema 校验。
- 模型不能直接执行 Shell、Git 或任意文件写入。
- 保存模型版本、输入摘要、输出动作和结果，支持失败回放。

### 5. 使用本机前台和 Trace 完成可视化

- 保持 Tauri 应用在前台，让用户直接看到真实鼠标移动、点击和输入。
- 先使用 Agent 对话输出、终端日志和 `agent-desktop` Trace 显示当前步骤和动作状态。
- 每个动作前后保存截图。
- 在截图或事件时间线上记录鼠标位置、点击类型、输入字段和结果。
- 保存失败步骤对应的 snapshot、日志和 Trace。

### 6. 实现问题收集

- 失败时自动生成问题卡片：标题、严重性、复现步骤、预期/实际结果、证据和疑似根因。
- 区分动作失败、断言失败、应用崩溃、数据持久化失败和环境失败。
- 首轮只处理真实可复现的业务缺陷，不注入临时缺陷。

### 7. 直接在当前分支执行修复闭环

- 将当前工作树状态记录为修复前基线。
- 允许 AI 直接修改当前分支。
- 每个问题最多尝试两轮。
- 每轮都重新执行原始场景，并运行相关已有测试。
- 修复通过后自动生成 Git commit；失败时停止并保留 Diff、日志和证据。

## 验收标准

- 在本机 macOS 上能启动目标 Tauri 开发版并通过权限自检。
- `agent-desktop` 能观察并操作首条流程所需的 Tauri 控件；若不能，已明确启用的替代适配器能完成同一流程。
- 运行期间用户能看到目标应用的真实鼠标移动、点击和输入。
- 测试使用唯一标识并在结束后自动清理。
- 关闭并重启后，记录仍存在且字段值完全一致。
- 至少发现一个真实、稳定、可复现的业务缺陷。
- AI 最多两轮修改后能让原始流程通过，或在失败时停止并保存完整证据。
- 修复通过后自动提交当前分支；提交包含可读的意图和验证信息。
- Agent 对话、Trace、截图、日志和 Git Diff 能回放运行步骤和问题详情；本地 Web 控制台属于后续 Runner 抽取阶段。

## 风险和应对

- **Tauri WebView 不暴露稳定 Accessibility 节点**：在第一步做 snapshot 验证；必要时使用 CDP/Playwright，不扩大桌面权限。
- **macOS 权限或锁屏导致误报**：启动前做权限和前台会话检查；运行期间禁止锁屏和睡眠。
- **现有业务流程没有可复现缺陷**：保持“寻找真实缺陷”的约束，不注入缺陷；PoC 可在问题发现阶段停止，不伪造修复成功。
- **AI 直接修改当前分支造成破坏**：每轮保存基线和 Diff，限制两轮，自动提交前必须完成原始流程和回归验证。
- **模型输入包含业务数据**：本地 PoC 只使用测试数据；模型请求记录脱敏，禁止把完整数据库或无关窗口内容发送给模型。
- **当前工作区不是 macOS**：Windows 工作区只能完成编排层和静态检查；真正的权限、Accessibility、鼠标效果和 Tauri 运行验证必须在本机 Mac 完成。

## 验证顺序

1. 权限和运行环境自检。
2. Tauri 窗口发现和 Accessibility Snapshot。
3. 单步点击、输入、断言和截图。
4. 完整创建/保存/重启/验证流程。
5. 真实缺陷复现和问题报告。
6. 修复、最多两轮复测和自动提交。
7. Agent 记录、Trace、截图、Git Diff 回放和最终人工检查。

## 后续何时需要 Runner

只有出现以下需求时才编写薄 Runner：

- 同一流程需要稳定重复运行多次。
- 不希望每次都依赖 Agent 对话上下文。
- 需要无人值守或定时执行。
- 需要多个 Mac Worker 并发。
- 需要云端租户隔离、计费和统一报表。

届时 Runner 只抽取已经验证过的能力：应用生命周期、动作执行、断言、证据采集和重试；不重新设计测试逻辑。
